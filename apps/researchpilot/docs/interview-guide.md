# 复试演示与讲解准备

## 90 秒项目介绍

「我做的是一个辅助理解 AI/CV 论文和代码仓库的研究工作台。科研复现时信息分散在论文、README、依赖和日志里，我希望让用户的每个判断都能回到可定位的证据。

系统用 FastAPI 提供接口，SQLite 保存项目、资料、任务与证据。论文按页分块，默认采用中英文 BM25 检索，可选向量检索并使用 RRF 融合。仓库通过 GitHub API 固定到 commit 获取文本，不执行未知代码。

在线模式中，一个 Agent 根据问题选择检索、文件读取、仓库概览和日志分析工具。我限制工具次数、校验参数和引用编号，并保存执行轨迹。为了无密钥也能复现演示，我把离线规则流程单独实现并明确标注。

目前已经验证本机应用、接口和合成检索数据集；真实论文集上的模型回答质量仍需要进一步评测。项目的难点是证据与生成结果之间的一致性，而不只是连接模型 API。」

这是一段基于当前实现的讲解示范。请先读懂代码、亲自运行和修改，再按自己真正掌握的内容表述，不要把工具辅助生成的工作全部当作自己已经独立掌握。

## 五分钟演示

1. 20 秒：说明科研复现的信息分散问题与只读边界。
2. 40 秒：导入示例，展示资料库页码、代码行号、示例标识。
3. 50 秒：问题「训练目标是什么」，点 E1 查看真实原文；解释检索排序而非编造摘要。
4. 60 秒：生成复现准备清单，展开 inspect_repository → search_evidence 的事件轨迹，解释离线路由与真实 LLM 规划的区别。
5. 40 秒：日志诊断显示 CUDA out of memory 的候选原因，不声称自动修复成功。
6. 30 秒：导出报告，刷新后打开历史记录，展示持久化。
7. 60 秒：展示测试与评测结果，主动说明合成开发集规模和下一步真实论文验证方案。

## 高频追问

**为什么不是 API 套壳？** 说明自己可控制与测试的部分：分块元数据、检索排序、来源固定、参数校验、工具预算、引用快照、任务恢复。不能单凭系统名称自证技术深度。

**Agent 与工作流的区别？** 当前离线是确定性工作流；在线路径让模型自主选工具和参数，工具输出再进入下一轮决策，预算与状态机限制范围。可以打开 `agent.py` 的 `online` 和 `offline` 对照解释。

**为什么不用 LangGraph？** 单 Agent 四工具的初期范围，用显式状态循环更透明。理解节点、状态、条件边与持久化问题比挂框架名称更重要。复杂化后能迁移，但当前没有使用。

**中文如何检索英文论文？** 离线通过可审计的中英科研术语词表扩展查询，可用中文检索英文证据，但不等于任意跨语言理解或翻译。可选多语 Embedding 后可提升召回，但需要真实数据评测；不能仅凭启用向量就断言更准确。

**为什么按页分块？** 保留引用定位，防止证据跨页拼接。代价是段落跨页和多栏顺序可能破碎。分块长度/重叠应在标注开发集上调参，而不是凭感觉选择后宣称最优。

**引用校验能消除幻觉吗？** 不能。它验证编号确实来自已读文本，不能验证模型结论被原文支持。还需引用支持度人工评分、无答案任务、对抗样例和低置信度退出机制。

**如何防 Prompt Injection？** 来源按不可信数据处理、无任意 shell/URL 工具、参数与项目边界校验。提示词不是唯一防线，结构性的工具权限更关键；不能宣称彻底解决提示注入。

**异步、并发、取消如何实现？** FastAPI 接受任务，3 线程池后台处理，SQLite 保存状态，前端轮询。取消在下一边界检查，无法立即打断当前 HTTP 请求。多进程/分布式需外部队列。

**性能提升多少？** 只引用 `evaluation-report.md` 中本次测得的数据，并明确它来自 16 题合成开发集。没有真实 LLM、GPU 或用户实验就不填写这类数字。

## 建议亲自完成的加深练习

2. 在 `diagnostics.py` 添加一种真实遇到的报错规则及测试。
3. 解释一次工具参数错误的日志，说明它如何反馈给模型。
4. 配置模型后跑同一题集，分别评估裸 LLM、RAG 与 Agent；保留失败案例和成本。
5. 修改一种分块策略，固定测试集后比较 Recall@K 与延迟，形成自己的技术决策。
