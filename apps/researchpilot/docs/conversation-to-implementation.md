# 原对话与实现映射

需求来源：[考研复试 Agent 方案](https://chatgpt.com/share/6ab69165-3e88-83ec-8735-8c2156d5974b)。已通过浏览器完整读取，公开分享内容是一条用户问题和一份八部分回答。

用户原始目标：独立开发一个可写入考研复试简历的 AI Agent，先确定做什么、完成需求分析和系统设计。本次要求进一步完善方案并实现；随后明确「暂时没有，先用离线演示」。

| 对话中的内容 | 本次落地 |
| --- | --- |
| 一、项目定位：ResearchPilot | 保持科研论文/代码/复现辅助目标，避免泛聊天定位 |
| 二、P0 四模块 | 解析检索、仓库分析、工具循环、复现计划均已实现；在线生成需模型服务 |
| 二、P1 日志诊断 | 已增加可解释规则与原文引用；模型也可调用此工具 |
| 二、P2 受控执行 | 保持后续扩展，当前不执行 shell 和仓库代码 |
| 三、单 Agent 系统架构 | FastAPI + 单 Agent + 工具注册 + SQLite，具备显式状态和预算 |
| 四、技术建议 | 保留 Python/FastAPI/GitHub/SQLite；其余按离线可运行和规模精简，详见架构 ADR |
| 五、六阶段开发路线 | 提供需求/设计文档、可运行应用、测试和评测、部署配置、复试讲解 |
| 六、量化评估 | 真实执行合成检索评测，不编造模型对比、GPU 结果或真实论文准确率 |
| 七、展示与简历 | 提供演示步骤和准确措辞；尚未公网部署或发布 GitHub 仓库 |
| 八、未决技术/验收选择 | 本次选定离线优先、可配置模型服务、明确各模块验收和能力边界 |

完善重点：引用可追溯、快照固定 commit、无证据显式说明、模式清晰区分、项目隔离、失败恢复、限额、重复导入幂等、错误脱敏、任务导出和测试可复现。

不将原对话中的建议当作未经实现的事实。当前版本没有使用 LangGraph/Chroma/React，不应在复试中列为已实现技术；也不能因为实现了模型适配器就声称在线模型已验证。
