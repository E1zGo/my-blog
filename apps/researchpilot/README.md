# ResearchPilot

基于证据检索与工具调用的科研实验辅助系统。面向 AI/CV 论文阅读、GitHub 仓库理解、复现计划整理与运行日志排查。

**当前默认离线演示，无需模型密钥、GPU 或前端构建工具。** 离线解析、BM25 检索、引用定位、仓库快照分析与日志规则是真实运行的；离线回答是证据摘录与规则清单，不是大模型推理。可配置兼容 Chat Completions 工具调用的服务后启用真实单 Agent。

**v0.9 已增加可选账号模式。** 默认仍为本机单人使用；可在侧栏「账号与权限」查看启用步骤。由你在本机创建管理员并设置密码，已有项目会迁入管理员账号。详见 [账号与迁移说明](docs/accounts.md)。

**v0.10 增加用量与运行状态、账号额度、低磁盘保护和部署检查。** 在侧栏「用量与运行」查看额度；博客入口和独立 HTTPS 子域名的部署方案见 [部署说明](docs/deployment.md)。当前仍默认本机离线，真实服务器、域名证书与公网大文件上传尚未验收。

## 快速启动

要求 Python 3.11 或更高。当前项目已创建 `.venv` 并安装依赖，可以在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn researchpilot.app:app --host 127.0.0.1 --port 8765
```

打开 [本地工作台](http://127.0.0.1:8765)；API 文档位于 [OpenAPI 文档](http://127.0.0.1:8765/docs)。也可双击 `start.bat` 或运行 `start.ps1`。若 8765 已启动，直接打开工作台，不必启动第二份服务。

全新环境安装：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m uvicorn researchpilot.app:app --host 127.0.0.1 --port 8765
```

Linux/macOS：`python3 -m venv .venv`，使用 `.venv/bin/python` 执行相同命令。`requirements-lock.txt` 是本次实际验证的完整依赖版本；开发测试用 `requirements-dev.txt`。前端为无外部 CDN 的 HTML/CSS/JavaScript，可完全离线加载。

## 两分钟演示

1. 点击「试试内置示例」，导入 4 页教学论文、4 个代码资料和 1 份日志。
2. 提问「这篇论文使用了什么方法与训练目标？」；点击回答中的 E1 查看页码与原文。
3. 选择「生成复现计划」，查看依赖、数据/权重、运行入口和待确认事项；展开工具执行过程。
4. 选择「日志诊断」，查看显存不足的匹配依据与排查建议。
5. 导出 Markdown 报告。在「任务记录」中重开任务；刷新页面后资料与记录仍保留。

TinyRestore 是**合成教学示例**，不对应真实发表的论文，代码片段不是一个可训练的完整模型仓库，没有真实实验分数。它用于验证 ResearchPilot 自身的流程。上传自己的 PDF / Markdown / TXT 或 LOG 即可替换示例。公开 GitHub 仓库导入需要联网，模型密钥不是必需的。

| 公网多用户部署 | 账号额度与运行探针已实现；HTTPS/服务托管模板已准备，真实部署和运维验收待完成 |

## 记录与比较实验（v0.4）

1. 在完成的「生成复现计划」任务中点击「转为实验记录」，或在「实验记录」中新建。填写实验目标、环境与硬件、数据集版本、代码 commit；参数按每行 `名称=值` 记录，建议包括随机种子和权重来源。
2. 实验由你在自己的环境执行，再人工填写状态、实际指标、评测划分与协议、个人结论。可勾选当前项目已导入的日志，保存时保留最多 20000 字符的日志片段快照（含原分块的重叠文字），截断会明确提示；完整内容仍在资料库。
3. 点击「复制设置开新实验」，沿用目标、环境、数据、参数和计划快照，清空指标、日志、结论及清单完成状态，便于开展新一轮尝试。
4. 展开「比较两次实验」，选择基准和对照。数据集/版本、划分、协议必须非空且逐字一致，单位必须一致（空表示无量纲），才计算同名指标的「对照 − 基准」差值。缺失或不一致时仅展示原始数值与原因；同时列出环境、代码、目标和参数的变化，不自动判断提升或因果关系。
5. 每条记录可导出 Markdown，也支持回收站恢复。每项目最多 500 条（含回收站），每实验最多 40 个参数、20 个指标和 10 份日志。指标名称不区分大小写去重，不同划分需使用不同名称。

计划与日志内容由服务端读取并保存快照，删除来源不会抹掉已保存的快照。每项目另有一份实验浏览器草稿；刷新后可恢复，正式保存才写入 SQLite。发生版本冲突时输入保留，需复制所需内容、放弃旧草稿后打开最新记录合并。手工标记「进行中」的实验不会因服务重启而改成失败，和 Agent 后台任务分开管理。对比仅使用已保存的记录，所有条件与数值均由用户提供，系统未自动执行或核验评测。

## 从日志记录指标（v0.5）

进入「实验记录」，展开「训练日志 · 指标与曲线」，导入 `.log` / `.txt` 日志并点击「分析日志」。也可以点「试用合成日志」查看演示；演示分数仅验证软件流程，不是真实实验成绩。

支持以下常见格式（单行键值或一行一个 JSON 对象）：

```text
epoch=1 step=100 train/loss=0.12 val/psnr=28.4dB val/ssim=0.84
{"epoch":2,"val":{"loss":0.08,"psnr":"29dB"}}
```

识别 loss、psnr、ssim、acc、accuracy、f1、precision、recall、lr、learning_rate、mse、mae；可用 train/val/test/eval 前缀（`/`、`_`、`.`、`-` 分隔）区分序列，也支持行首 `[train]`、`[val]` 等或 JSON 的 split/phase 字段。仅采用同一行明示的 step/epoch 和划分；不从上一行继承。单位仅识别明示的 dB 或 %，其他单位请在实验中核对填写。不同单位的序列分开展示，不自动换算百分数。

每组序列优先以全部点均有的 step 为横轴，其次 epoch，否则使用日志行号。重复/回退坐标保留并断开曲线，避免把多轮训练拼成连续趋势；图表按原始顺序连接，不平滑或合并数据。可选最后记录、最小值、最大值或任意记录点，查看真实行号与原文。数值最小/最大不表示最优模型或成功复现。

点击「确认此值，加入实验草稿」会加入当前项目已有草稿，或新建实验草稿；不会覆盖同名指标，也不会自动正式保存。补充实验名称、数据集版本、评测协议后保存，服务端重新核对日志文本校验值、记录点及数值，留存原始行证据。数值锁定以保持可追溯；点击「改为手动记录」可修改，同时解除该指标的日志来源关联。单位、划分和协议始终需要人工核对，系统未验证实验本身。

新导入日志额外保留完整文本，和检索用的重叠片段分开。旧日志有原文件时可直接分析；两者都没有时会要求重新导入同名日志补齐，不把检索片段拼接为曲线。已保存的指标证据在原日志删除后仍保留，Markdown 导出包含来源、行号、校验值和原文。实验复制仍清空结果与指标证据。

单次最多处理 **50000 行、2000 个指标点、32 组序列**，单行最多 4096 字符。达到上限时仅展示前部结果并明确提示，最后/最小/最大值也只针对已解析部分。跳过 NaN/Infinity、绝对值超过 1e100、同一行重复指标、格式异常 JSON 和超长行；不识别任意 TensorBoard 二进制、CSV 或自定义日志格式。现有 100 万字符文本上限继续适用。没有识别到指标可手动记录，没有匹配错误规则也不表示运行成功。

## 按页精读论文（v0.7）

1. 打开论文后，页码和阅读方式自动保存在当前浏览器；再次打开时继续上次位置。「查看 PDF 原文」的放大比例也会保存。引用或笔记指定的页码优先于阅读进度。
2. 点击阅读器的「问当前页」，自动选定这篇论文和当前页，回到问答框；填写问题后才开始任务。也可以在资料库只勾选一篇论文，点击「限定页码」，输入起止页（两端均包含）。页码按 PDF 文件的实际页序计数，可能不同于论文印刷页码；跨页公式请同时包含相邻页。
3. 全文检索和新问答仅使用所选页内证据；没有匹配时不会扩大到整篇或其他资料。任务记录与报告保留发起时的范围。点击「恢复全文」解除页码限制，仍保留所选论文；改变资料选择也会清除页码限制并提示。复现计划和日志诊断需要先恢复全文。
4. 点击「写本页笔记」，填写个人分析并保存。笔记固定关联论文和页码，可从笔记跳回原文；导出也保留页码。它不会自动摘录页面或生成公式解释；要保留原文证据，请在整理文本中「收藏此段」。已有未保存笔记草稿时会先打开旧草稿，避免覆盖。

阅读进度和待用页码范围保存在本浏览器，清除浏览器数据会丢失，不包含在 `data/` 备份中。正式保存的笔记及任务范围在 SQLite 中；页级笔记的来源和页码保存后不可修改，删除来源仍保留笔记内容，但无法再打开原文件。本阶段继续使用离线术语匹配，不需要模型密钥，也没有增加任意跨语言翻译能力。

## 自检、完整备份与恢复（v0.8）

点击导航栏的「自检与备份」，查看环境、数据库完整性、已保存原文件和可用磁盘；点击「下载完整备份 ZIP」保存全部项目的数据。先保存重要笔记并等待导入/研究任务结束。备份涵盖数据库、已保存原文件、历史任务、笔记、实验记录及回收站；浏览器草稿/阅读进度、`.env` 配置、密钥和旧备份文件不在包内。示例或旧资料本来没有原文件副本时，会明确提示，并保留现有提取文本。

也可在项目目录使用命令行（Linux/macOS 替换 Python 路径为 `.venv/bin/python`）：

```powershell
.\.venv\Scripts\python.exe -m researchpilot.maintenance doctor
.\.venv\Scripts\python.exe -m researchpilot.maintenance backup --output "data/backups/researchpilot-20260928.zip"
.\.venv\Scripts\python.exe -m researchpilot.maintenance verify "data/backups/researchpilot-20260928.zip"
.\.venv\Scripts\python.exe -m researchpilot.maintenance restore "data/backups/researchpilot-20260928.zip" --to "data-restored"
.\.venv\Scripts\python.exe -m researchpilot.maintenance doctor --data-dir "data-restored"
```

恢复仅接受尚不存在的新目录，不覆盖当前项目。确认恢复结果后停止服务，将 `.env` 中 `RP_DATA_DIR` 改为 `./data-restored` 后重启；相对路径从项目目录解析。保留原目录即可切回。版本过新、文件缺失、校验失败、异常路径或数据库不完整的备份会被拒绝。校验用于检查文件损坏，请使用本人保存且可信的备份；它不是备份来源的数字签名。

备份使用 SQLite 一致快照和原文件 SHA256，不复制运行中的主数据库文件来代替快照。正在运行的任务会阻止备份；快照后的新操作不包含在此次备份中，备份期间请避免移除资料。原文件缺失时整个备份失败，不交付不完整包。当前备份总量限 10 GB、10000 个条目，清单最大 4 MB。预留至少约两倍待备份数据量的可用空间；校验也会暂时展开文件。网页生成文件在下载响应结束后清理，命令行 `--output` 的文件由用户保留；备份仍在同一磁盘时不能防范该磁盘损坏。

本机交付包可运行 `.\.venv\Scripts\python.exe scripts/build_release.py` 生成，默认输出到 `artifacts/releases/`；只包含源码、示例、依赖锁定文件、测试与文档，不打包个人资料或虚拟环境。新电脑需先安装 Python 和依赖，依赖安装通常需要联网，完成后可离线演示。发布与升级流程见 [本机交付说明](docs/local-release.md)。

## 以后接入模型

复制 `.env.example` 到 `.env`，编辑后重启服务：

```dotenv
RP_MODE=llm
RP_API_BASE=https://你的服务地址/v1
RP_API_KEY=在本机填写密钥
RP_MODEL=支持工具调用的模型名称
RP_EMBED_MODEL=
```

`RP_API_BASE` 需包含服务要求的 API 前缀，程序在其后追加 `/chat/completions` 或 `/embeddings`。本地 Ollama 等服务可使用 `http://localhost:11434/v1`，模型须支持工具调用；本机服务可留空密钥。并非所有模型都兼容 Chat Completions 的工具协议，例如要求 Responses API 的模型不能直接使用。参考 [官方工具调用文档](https://developers.openai.com/api/docs/guides/function-calling)。当前未使用真实密钥做在线模型验收。

设置 `RP_EMBED_MODEL` 后，新导入资料会生成向量，并与 BM25 排名进行融合。旧资料保留原索引；如需重建，可移除并重新导入。向量附带服务地址与模型标识，检索不会混用不同配置的向量。小规模使用 SQLite 保存向量并精确计算相似度，未引入 Chroma。

**数据流：** 离线模式不访问模型服务；导入公开 GitHub 仓库只向 GitHub 请求公开内容。启用 LLM 后，问题、近期回答和工具返回片段会发送到你配置的模型服务；启用 Embedding 后，导入文本也会发送到该服务。密钥仅从服务端环境读取，不进入前端和仓库。

## 项目结构

```text
researchpilot/
  app.py          FastAPI API、任务线程池、本机访问边界
  agent.py        单 Agent 状态循环、工具协议、离线规则路径、引用校验
  library.py      资料解析、索引入库、检索与去重
  imports.py      后台导入、原文件保存、取消与重启清理
  preview.py      PDFium 本机逐页渲染，限制预览像素尺寸
  notebook.py     证据快照、阅读笔记、版本校验与 Markdown 导出
  reading.py      单篇论文页码范围校验与范围标签
  maintenance.py  本机自检、完整备份、逐文件校验和新目录恢复
  experiments.py  人工实验记录、计划/日志快照、设置复制与指标对比
  log_analysis.py 完整日志的有界解析、指标点定位与来源核对
  retrieval.py    页内分块、BM25、余弦相似度与 RRF
  github.py       固定提交的只读 GitHub 导入器
  provider.py     模型与 Embedding 服务适配、错误脱敏
  diagnostics.py 日志规则与候选原因
  db.py           SQLite 模型与事件存储
frontend/         中文响应式工作台，无构建步骤和外部资源
examples/         标识清楚的合成演示资料
tests/            可离线运行的自动测试
evals/            带来源/页码标注的问题集
scripts/          评测脚本
docs/             需求、设计、验收、复试材料与评测结果
data/             本机数据（自动创建，不提交 Git）
```

## 本机运行与维护

默认监听 `127.0.0.1`。保持**单进程/单 worker**运行；多个进程会影响任务恢复语义。停止后复制 `data/` 可备份数据库；运行中不要只复制 SQLite 主文件而漏掉 WAL。服务重启会把未完成任务标记为失败，资料、已完成任务及引用快照保留；请重新发起中断任务。

每个项目最多 5000 个片段；单文件上传默认最大 **200 MB**、PDF 最大 300 页、文本最多 100 万字符。可在 `.env` 通过 `RP_MAX_UPLOAD_MB=200` 配置上限（支持 1–512，1 MB 按 1024×1024 字节计算），重启服务并刷新网页后生效。界面从后端读取同一个限制，无需修改代码。Docker Compose 同样支持该环境变量。

选择文件后，上方「文件导入状态」显示每份文件的大小、传输进度、实际提取页数、索引阶段和最终结果。文件被服务端接收后在后台处理，刷新页面可恢复最近 100 条导入记录；「收起已结束记录」只折叠显示。超过大小限制、加密 PDF、无可提取文字（需 OCR）、页数/文本超限等原因会单独显示。最多同时解析 2 份、接收 8 个未结束任务；取消在页边界或提交索引前生效，服务中断的导入会在重启后标记失败，需要重新上传。若提示无法连接本机服务，请运行 `start.bat` 后重试。

在「资料库」可使用中文科研术语检索英文论文，例如「低光照增强如何估计退化模型」「论文的主要贡献是什么」「公式8」。界面显示实际使用的中英术语对应与英文证据。离线模式使用内置词表与 BM25，不进行任意跨语言语义理解、全文翻译或生成中文解释；未覆盖的表达可以补充具体术语。

打开 PDF 默认进入「原版阅读」，按页显示本机渲染的真实页面，公式、上下标和双栏版式得以保留；「整理文本」合并断行、修正常见连字与行尾断词，按章节和句子分块，并折叠公式、图表及算法的提取字符。章节可跳转，长段与页内节选会标记；复杂阅读顺序仍以原版为准，不声称从 PDF 恢复准确 LaTeX。图片预览不支持选择文字，复制与收藏请使用整理文本。旧论文可点击「更新论文索引」，后台完成后重新打开；失败或取消保留旧索引，资料 ID、原文件及历史任务/笔记快照保持不变。

原文件保存在 `data/originals/`，和数据库一起备份。**升级前已导入的资料没有原文件副本，需要重新上传同名、相同内容的 PDF 补齐**；会沿用原资料 ID，必要时升级段落索引。删除资料时同时移除原文件与索引，已有报告的文字证据快照保留。原文件正在下载而暂时不能删除时，会在下次启动清理。本版新增 pypdfium2 与 Pillow 依赖；旧环境请运行 `.venv/Scripts/python.exe -m pip install -r requirements-lock.txt` 后重启。

在检索结果点击「收藏证据」、提取文本点击「收藏此段」，或打开任务引用后点击「收藏到研究笔记」，可以保存该片段的原文和页码。相同片段重复收藏不会覆盖已有分析；若已在回收站，会恢复原笔记。原文由服务端从真实片段或任务快照读取，不接受前端伪造的证据文字。

「研究笔记」支持新建综合笔记、关联资料、编辑分析，并按阅读笔记/方法与创新/实验设置/结果与局限/待验证问题分类。每个项目可保存最多 1000 条（含回收站）。原文证据不能编辑，个人分析单独填写；没有自动生成或验证科研结论。删除来源后，已保存的证据和分析仍在，但原文件入口会失效。

编辑内容会先存为**当前浏览器、当前项目的一份草稿**，刷新后点击「恢复未保存草稿」继续；点击「保存笔记」才写入项目数据库。草稿不在 `data/` 备份中，清除浏览器数据会丢失，重要分析请及时保存。若另一页面已改动同一笔记，保存返回冲突并保留草稿，不直接覆盖；可先复制需要合并的文字，放弃旧草稿，打开最新笔记再合并。回收站支持恢复，导出 Markdown 包含当前项目全部正常笔记，排除回收站。

大文件并不一定难以检索，文件体积可能主要来自图片；小文件也可能是没有可提取文字的扫描件。复杂公式、多栏排版、图片型 PDF 的提取质量仍需人工检查。仓库文件读取有大小与数量限制，页面会显示导入警告，不承诺覆盖完整仓库。

Docker 配置见 `compose.yaml`：`docker compose up --build`，仍只映射到本机 8765，数据卷持久化。Docker 打包文件已提供，当前未在 Docker 引擎中实际构建验证。
